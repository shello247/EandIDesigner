# Consolidated application release — 12 October 2026

## Scope

This release consolidates the current engineering application and the completed
Package Information/Sheet Loader workflow. It preserves controlled Device Types,
versioned engineering profiles, component persistence, compact drawing settings,
canvas toolbar, cursor placement and manual panel labels.

- Package Information replaces the old Front Matter display label and opens
  expanded. Its Title Sheet applies to the complete package, not Section 1.
- Add Section creates a named section and its own title page. Add Sheet requires
  a named destination or creates a section with its first working sheet atomically.
- Legacy unsectioned working sheets show Needs section. They are never moved or
  saved simply by opening a drawing.
- Existing Item revisions, Symbol versions, equipment identities, wires, labels
  and BOM quantities remain authoritative and unchanged by the UI rollout.

See [feature 4](../features/drawing-packages/README.md) and the
[classification module](../../../src/features/device_classification/README.md).

## Development and deployment boundaries

Run the shared local application from the qualified linked worktree with
`npm run dev:webpack`. The launcher resolves canonical main storage explicitly.
Do not point a development worktree at its own `file:./dev.db`.
Never run general bootstrap/seed commands against an existing production catalogue.

This Sheet Loader release requires no storage migration. The consolidated
classification implementation includes a nullable SymbolVersion Device Type
column. Existing installations must inspect their schema and use the guarded
`scripts/upgrade-device-classification-storage.ts` dry-run/backup/verification
procedure if that additive upgrade has not already been applied. Earlier
engineering-profile upgrade prerequisites also remain applicable; do not assume
an old database is compatible merely because dependencies install.

Do not restore an old database backup over later engineering work. Software
rollback and data restoration are separate operations. Keep the current source
and database recovery copies outside the public repository.

Use a saved-draft maintenance window for builds that share the live worktree's
Next output. Stop only the verified owned application runtime.

```powershell

npm run lint

$env:AUDIT_PHASE='unique-release-check'
node scripts/drawing-performance-audit/run-command.mjs bootstrap node node_modules/tsx/dist/cli.mjs scripts/bootstrap-sqlite.ts
node scripts/drawing-performance-audit/run-command.mjs build node node_modules/next/dist/bin/next build --webpack

```

The guarded drawing gate retains the earlier production regression set and adds
classification, settings, labels, toolbar and Package Information coverage.
Chromium and Firefox use synthetic SQLite, one worker, no retries and port 3121.
An occupied port is an error, not permission to stop another application.
Locally, the runner requires an explicitly registered workspace worktree;
GitHub Actions uses its independently guarded checkout and synthetic database.

## Known boundaries

- A software release is not a completed catalogue/manufacturer engineering audit.
  Classification/evidence gaps must remain visible until individually reviewed.
- No live drawings are rearranged or saved by release verification.
- Schematic and assurance views retain their stated provisional/read-only limits.
- The approved development-tooling-only GHSA-vfj7-8cjw-p6xm exception expires
  at the end of 22 October 2026 UTC. Production dependencies have a separate
  zero-exception gate; the policy fails closed after expiry or for unrelated findings.
- Customer record inventories, manuals, engineering screenshots, backups and
  private delivery evidence are deliberately excluded from public publication.

Final verification results and publication identity belong in the public release
receipt; local detailed traces remain in guarded ignored artifact directories.
